# 油品价格维护（离线并发一致性版）

- 行业：石油
- 技术栈：Vue 3、Vite、TypeScript、Pinia 可扩展、localStorage
- 启动：`npm install && npm run dev`
- 构建：`npm run build`

## 已实现的一致性规则

1. **油品修订号（乐观锁）**
   - 每个油品维护当前 `revision`。
   - 终端提交时携带本地基线 `baseRevision`。
   - 基线过期或向旧价格窗口写入时，不覆盖有效价，转为“冲突草稿”。
   - 冲突草稿可由站长按最新修订重提。

2. **价格时间轴唯一有效价**
   - 同一油品、同一生效时刻只保留一条 `active` 价格。
   - 新价提交到同一时刻后，旧价标记为 `superseded`，但仍保留查询。
   - 时间轴同时展示“当前差额”和“提交时原差额”。

3. **调价批次幂等续传**
   - 批次内每项使用 `${batchId}:${itemId}` 作为 `requestId`。
   - 写入失败后保留完整批次和每项结果；继续提交时跳过已写入项。
   - 重试不会生成第二条价格版本，也不会重复计算差额。
   - 批次内的冲突项会进入冲突草稿，不阻塞后续项处理。

4. **班次交接离线合并**
   - A/B 两端同字段的改动并列保存，不做单端覆盖。
   - 双端字段不同且都改过基线值时，进入字段级冲突，必须由站长选择 A 或 B。
   - 交接包未经站长确认，交接报价不写入价格时间轴，也不参与当前均价。

5. **价格变动导致交接项失效重算**
   - 已到期的新价生效后，所有未确认交接包中对应油品的当前条目标记为 `invalidated`。
   - 系统基于新价生成新一代交接项；旧条目、旧基线和原差额仍可在“交接代际”中查询。
   - 新代条目保留非报价字段的历史选择，报价冲突需要重新裁决。

6. **均价口径**
   - 均价只读取已到期且 `active` 的当前版本。
   - 冲突草稿、历史版本和未确认交接价均不参与均价。

页面内置了一个旧窗口冲突草稿、一个中断批次和一个待确认交接包，可直接复现：

- 打开批次卡片点击“从完整批次继续”。
- 对未确认交接包点击“模拟双端离线改动”，再“离线合并”。
- 先提交新价观察交接项自动生成下一代，再回到旧代查看原差额。
- 在调价表单中改小“客户端基线修订号”，提交后观察冲突草稿。
